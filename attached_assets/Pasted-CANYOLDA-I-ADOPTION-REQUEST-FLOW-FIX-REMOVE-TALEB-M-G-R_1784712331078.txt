==================================================
PART 3 — REQUIRED ADOPTION REQUEST LOGIC
==================================================

Sahiplenme talebi mantığı şu şekilde çalışmalı:

USER A:
İlanı yayınlayan kişi.

USER B:
İlanı gören ve sahiplenme talebinde bulunan kişi.

Akış:

1. User B ilan detayında “Sahiplenme Talebinde Bulun” butonuna basar.

2. Backend bir adoption request kaydı oluşturur.

Kayıt en az şu ilişkileri korumalı:

- listingId
- listingOwnerId / recipientUserId = User A
- requesterUserId = User B
- status
- createdAt

3. User A’ya bildirim oluşturulur.

Bildirim anlamı:

“{User B} ilanınızla ilgileniyor ve sizinle konuşmak istiyor.”

Bildirimde şu ilişkiler bulunmalı:

- type: adoption_request
- actorUserId: User B
- recipientUserId: User A
- listingId
- adoptionRequestId
- conversationId varsa conversationId

4. User A bildirime dokunduğunda ilgili talep veya sohbet akışı açılmalı.

5. User A ve User B mesajlaşabilmeli.

==================================================
PART 4 — CONVERSATION CREATION
==================================================

Aynı ilan ve aynı iki kullanıcı için tekrar tekrar farklı sohbet oluşturma.

Conversation oluşturulurken:

- mevcut konuşma varsa onu kullan
- yoksa yeni konuşma oluştur

Conversation katılımcıları:

- listing owner / User A
- requester / User B

Conversation ilanla ilişkilendirilebiliyorsa:

- listingId saklanmalı

Önerilen backend davranışı:

findOrCreateConversation({
  listingId,
  userAId: listingOwnerId,
  userBId: requesterUserId
})

Aynı kullanıcı kendisiyle sohbet başlatamamalı.

İlan sahibi kendi ilanına talep gönderememeli.

==================================================
PART 5 — WHEN CHAT SHOULD OPEN
==================================================

Mevcut ürün mantığını incele ve tek, tutarlı akış uygula.

Tercih edilen davranış:

- User B talebi gönderir.
- User A bildirim alır.
- User A bildirime dokunduğunda mevcut veya yeni conversation açılır.
- User A ile User B sohbet eder.

Eğer mevcut sistem talep gönderildiği anda conversation oluşturuyorsa bunu bozma; ancak User B’yi başarı ekranından “Talebimi Gör” gibi gereksiz bir sayfaya yönlendirme.

Talep gönderildikten sonra başarı ekranında yalnız:

“Tüm İlanlara Dön”

bulunmalı.

PART 7 — DUPLICATE REQUEST PROTECTION
==================================================

Aynı User B, aynı ilana tekrar talep gönderirse:

- duplicate adoption request oluşturma
- duplicate notification oluşturma
- duplicate conversation oluşturma

Mevcut talep varsa uygun translated bilgi mesajı göster.

Örnek:

“Bu ilan için zaten bir talep gönderdiniz.”

İş mantığında mevcut bir unique constraint veya kontrol varsa koru ve doğrula.
