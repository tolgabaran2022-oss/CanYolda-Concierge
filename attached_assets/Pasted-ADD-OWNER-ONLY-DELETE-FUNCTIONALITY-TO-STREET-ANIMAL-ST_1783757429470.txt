ADD OWNER-ONLY DELETE FUNCTIONALITY TO STREET ANIMAL STATUS CARDS.

CURRENT SCREEN:
"Sokak Hayvanları" screen contains street animal status/report cards.

Examples:
- "Not eklenmemiş"
- "Yaralı hayvan"
- Acil
- Bekleyen
- Sağlıklı

REQUIRED FEATURE:

The user who originally created a street animal status/report card must be able to delete their own report.

IMPORTANT:
Only the creator/owner of the report can see and use the delete action.

Other users must NOT:
- see the delete button
- delete the report
- trigger the delete API manually

This must be enforced both in the UI and Supabase database security.

6. SECURE DELETE QUERY

After confirmation, verify the authenticated user again.

Example logic:

const {
  data: { user },
} = await supabase.auth.getUser();

if (!user) {
  throw new Error('Oturum bulunamadı');
}

Then delete only when:
- report ID matches
- report owner ID matches current authenticated user ID

Example:

const { error } = await supabase
  .from('street_animal_reports')
  .delete()
  .eq('id', report.id)
  .eq('created_by', user.id);

Use the actual project table and ownership field.

IMPORTANT:
Never execute:

.delete().eq('id', report.id)

alone.

The delete request must also verify ownership.

7. SUPABASE RLS DELETE POLICY

Inspect Row Level Security on the real street animal reports table.

Create or fix a DELETE policy so users can only delete their own reports.

Expected policy logic:

auth.uid() = created_by

Example SQL:

CREATE POLICY "Users can delete their own street animal reports"
ON public.street_animal_reports
FOR DELETE
TO authenticated

Adapt:

- ownership column

to the current real database structure.
