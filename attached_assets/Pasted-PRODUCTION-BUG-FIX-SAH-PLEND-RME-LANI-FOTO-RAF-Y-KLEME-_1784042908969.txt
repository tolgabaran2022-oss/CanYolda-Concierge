PRODUCTION BUG FIX — SAHİPLENDİRME İLANI FOTOĞRAF YÜKLEME / MULTI IMAGE UPLOAD

Referans ekran görüntüsündeki “İlanı Düzenle” sayfasını ve mevcut proje kodunu incele.

Şu anda “Fotoğraflar” bölümünde 1/10 yazıyor ve “Fotoğraf Ekle” kartı bulunuyor. Ancak ilk fotoğraftan sonra ikinci, üçüncü ve diğer fotoğraflar eklenemiyor.

BU SORUNU YÜZEYSEL BİR UI DEĞİŞİKLİĞİYLE ÇÖZME.

Fotoğraf seçme, local state, upload, storage, database, ilan oluşturma, ilan düzenleme, veri okuma ve yeniden render akışını uçtan uca incele ve gerçek root cause'u bul.

AMAÇ:

Kullanıcı bir sahiplendirme ilanına minimum 1, maksimum 10 adet fotoğraf ekleyebilmeli.

Örnek:

Başlangıç:
[Fotoğraf 1]

Kullanıcı “Fotoğraf Ekle” butonuna basar ve yeni fotoğraf seçer.

Sonuç:
[Fotoğraf 1]
[Fotoğraf 2]

Tekrar fotoğraf ekler:

[Fotoğraf 1]
[Fotoğraf 2]
[Fotoğraf 3]

Mevcut fotoğraflar ASLA yeni fotoğraf seçildiğinde silinmemeli veya replace edilmemeli.

2. IMAGE STATE ARRAY OLMALI
==================================================

Sahiplendirme ilanı fotoğraf state'i tek bir string veya object olmamalı.

Yanlış:

const [image, setImage] = useState(null);

Doğru mantık:

const [images, setImages] = useState<ImageItem[]>([]);

ImageItem için mevcut proje mimarisine uyumlu bir type oluştur.

Örneğin:

type ImageItem = {
  id: string;
  uri: string;
  storagePath?: string;
  uploadedUrl?: string;
  isExisting?: boolean;
};

Mevcut projede farklı bir image type sistemi varsa onu bozma ve mevcut type sistemini düzgün şekilde genişlet.

4. IMAGE PICKER MULTI IMAGE SUPPORT
==================================================

Proje Expo / React Native ise mevcut Expo ImagePicker implementasyonunu düzelt.

Picker mevcut project dependency sürümüne uygun şekilde kullanılmalı.

Mümkünse multiple selection destekle.

Ancak bazı platformlarda veya picker implementasyonlarında kullanıcı tek fotoğraf seçerse bile aynı “Fotoğraf Ekle” butonuna tekrar tekrar basarak yeni fotoğraflar ekleyebilmeli.

Seçilen yeni fotoğrafları mevcut array'e APPEND et.

Örnek mantık:

setImages(prevImages => {
  const availableSlots = 10 - prevImages.length;

  const imagesToAdd = newImages
    .filter(valid image)
    .slice(0, availableSlots);

  return [...prevImages, ...imagesToAdd];
});

ASLA:

setImages(newImages);

kullanarak mevcut listeyi overwrite etme.

9. FOTOĞRAF SİLME
==================================================

Her fotoğraf üzerindeki X butonu yalnızca seçilen fotoğrafı silmeli.

Örnek:

const handleRemoveImage = (imageId: string) => {
  setImages(prev => prev.filter(image => image.id !== imageId));
};

Yanlışlıkla tüm images array temizlenmemeli.

Kapak fotoğrafı silinirse kalan array içerisindeki yeni index 0 otomatik kapak olmalı.

Minimum 1 fotoğraf zorunluysa kaydetme sırasında validation göster.

Kullanıcı fotoğrafı UI'dan sildiğinde mevcut storage dosyasını hemen hard delete etmek veri kaybına yol açabilecekse güvenli pending deletion sistemi kullan.

Save başarılı olduktan sonra orphan cleanup mantığını uygula.

15. DATABASE SCHEMA AUDIT
==================================================

Sahiplendirme ilanı tablosunu incele.

Fotoğraflar şu anda tek bir image_url string alanına kaydediliyorsa bunu production-safe multi-image yapısına taşı.

Mevcut schema ile uyumlu en doğru çözümü seç:

Option A:

image_urls text[]

Option B:

images jsonb

Option C:

normalized listing_images table

Mevcut proje mimarisine göre en güvenli yapıyı seç.

Ancak tek image_url alanı multi image için source of truth olarak kullanılmamalı.

Legacy ilanları bozma.

Migration gerekiyorsa migration oluştur.

Eski:

image_url = "photo1.jpg"

kayıtlarını kaybetme.

Migration sonrası örnek:

image_urls = ["photo1.jpg"]

olmalı.

Production database'e destructive reset uygulama.

Tabloyu drop etme.

Mevcut ilanları silme.
