CAN YOLDAŞI UYGULAMASI — İLAN DÜZENLE FOTOĞRAF EKLEME SİSTEMİNİ KÖKTEN DÜZELT

Uygulamadaki mevcut tasarımı ve görsel düzeni BOZMA.

Özellikle şu akışta bulunan fotoğraf ekleme sistemini production seviyesinde tamamen denetle ve düzelt:

İlanlarım
→ mevcut ilana gir
→ İlanı Düzenle / İlan Düzenle
→ Fotoğraflar
→ Fotoğraf Ekle
→ Fotoğraf Ekle bottom sheet

Mevcut durumda bottom sheet doğru şekilde açılıyor ve kullanıcıya şu seçenekler gösteriliyor:

- Kameradan Çek
- Galeriden Seç
- Vazgeç

ANCAK:

"Kameradan Çek" seçeneğine basıldığında kamera açılmıyor.

"Galeriden Seç" seçeneğine basıldığında galeri / fotoğraf seçici açılmıyor.

Bu problemi sadece görsel olarak düzeltme.

Gerçek native fotoğraf seçme sistemini uçtan uca çalışır hale getir.

==================================================
1. ÖNCE ROOT CAUSE AUDIT YAP
==================================================

Fotoğraf ekleme sistemiyle ilişkili bütün dosyaları recursive olarak tara.

Şunları kontrol et:

- Edit listing screen
- İlan Düzenle ekranı
- Photo section component
- Photo upload component
- BottomSheet component
- Modal component
- ImagePicker helper
- Media picker service
- Upload service
- Listing form state
- Listing update mutation
- Storage upload logic
- Supabase Storage entegrasyonu
- Expo config
- app.json
- app.config.js
- app.config.ts
- Android permission configuration
- iOS permission configuration

Özellikle aşağıdaki hataları ara:

- onPress tanımlı değil
- yanlış callback bağlanmış
- boş arrow function kullanılmış
- placeholder fonksiyon kullanılmış
- TODO fonksiyon kullanılmış
- fonksiyon çağrılmadan sadece referansı verilmiş
- yanlış scope
- stale closure
- disabled prop yanlış
- pointerEvents sorunu
- overlay touch event'i engelliyor
- BottomSheet gesture touch event'i yutuyor
- Pressable çalışmıyor
- TouchableOpacity event'i tetiklenmiyor
- parent component touch event'i intercept ediyor
- async function await edilmiyor
- unhandled promise rejection
- permission request eksik
- ImagePicker import yanlış
- deprecated ImagePicker API kullanılıyor
- API response formatı yanlış okunuyor
- result.cancelled / result.canceled farkı
- assets array okunmuyor
- URI state'e eklenmiyor
- bottom sheet kapanmadan picker çağrıldığı için native modal açılmıyor
- modal presentation conflict
- iOS native presentation conflict
- Android activity conflict
- web implementation eksik

Önce gerçek root cause'u bul.

Tahmin ederek sadece yeni buton ekleme.

Mevcut çalışan yapıyı analiz ederek problemi kökten düzelt.

4. BOTTOM SHEET VE NATIVE PICKER ÇAKIŞMASINI DÜZELT
==================================================

Önemli:

Native kamera veya galeri picker'ı açılmadan önce mevcut bottom sheet / modal güvenli şekilde kapatılmalı.

Şu akışı uygula:

1. Kullanıcı seçeneğe basar.
2. Bottom sheet kapanır.
3. Bottom sheet dismiss işlemi tamamlanır.
4. Native picker çağrılır.

Gerekirse:

- onDismiss
- requestAnimationFrame
- InteractionManager.runAfterInteractions
- kısa UI transition synchronization

gibi projeye uygun güvenli yöntemlerden birini kullan.

Ancak gereksiz random timeout hack'i kullanma.

Bottom sheet açıkken native picker çağırarak iOS'ta presentation conflict oluşturma.

==================================================
5. KAMERADAN ÇEK AKIŞI
==================================================

Kullanıcı "Kameradan Çek" butonuna bastığında şu akış eksiksiz çalışmalı:

1. Bottom sheet kapanır.
2. Kamera permission durumu kontrol edilir.
3. Permission daha önce verilmemişse sistem permission dialog açılır.
4. Kullanıcı izin verirse gerçek cihaz kamerası açılır.
5. Kullanıcı fotoğraf çeker.
6. Kullanıcı fotoğrafı onaylarsa sonuç alınır.
7. Fotoğraf ilan fotoğrafları state'ine eklenir.
8. UI anında güncellenir.
9. Sayaç güncellenir.
10. Kaydet butonuna basıldığında fotoğraf backend/storage sistemine yüklenir.
11. İlan kaydı yeni fotoğraf URL'siyle güncellenir.

Expo ImagePicker kullanılıyorsa güncel API mantığına uygun şekilde:

requestCameraPermissionsAsync

ve:

launchCameraAsync

kullan.

Result kontrolünde güncel API response yapısını kullan.

Örneğin:

result.canceled

kontrol et.

Başarılı sonuçta:

result.assets

içerisindeki asset'leri işle.

Eski ve deprecated:

result.cancelled

mantığını körü körüne kullanma.

Projede kullanılan Expo SDK/API sürümüne göre doğru field'ı doğrula.

==================================================
6. GALERİDEN SEÇ AKIŞI
==================================================

Kullanıcı "Galeriden Seç" dediğinde:

1. Bottom sheet kapanır.
2. Gerekli media library permission kontrol edilir.
3. İzin gerekiyorsa native sistem izin ekranı açılır.
4. Galeri / photo library açılır.
5. Kullanıcı fotoğraf seçer.
6. Seçilen fotoğraf sonucu alınır.
7. Fotoğraf ilan fotoğraf listesine eklenir.
8. UI anında güncellenir.
9. Sayaç güncellenir.
10. Kaydet işleminde upload edilir.

Expo kullanılıyorsa:

requestMediaLibraryPermissionsAsync

ve:

launchImageLibraryAsync

kullan.

Sadece fotoğraf seçilebilsin.

Video seçimi kapalı olsun.

Media type sadece image olacak şekilde ayarla.

==================================================
7. MULTIPLE PHOTO SİSTEMİ GERÇEKTEN ÇALIŞSIN
==================================================

İlan başına maksimum 10 fotoğraf destekleniyor.

Mevcut UI:

1/10

şeklinde sayaç gösteriyor.

Bu gerçek state verisine bağlı olmalı.

Örneğin:

photos.length / 10

mantığında hesaplanmalı.

Hardcoded "1/10" bırakma.

Kullanıcı galeriden fotoğraf eklediğinde:

1/10
→
2/10

sonra:

3/10

şeklinde gerçek zamanlı güncellenmeli.

Kullanıcı maksimum 10 fotoğrafa ulaşırsa:

Fotoğraf Ekle alanını disable et veya gizle.

Kullanıcı yeni fotoğraf eklemeye çalışırsa uygun Türkçe uyarı göster:

"En fazla 10 fotoğraf ekleyebilirsiniz."

10 fotoğraf limitini hem UI hem handler seviyesinde kontrol et.

Sadece UI kontrolüne güvenme.

==================================================
8. GALERİDEN ÇOKLU FOTOĞRAF SEÇİMİNİ DESTEKLE
==================================================

Platform ve mevcut picker API destekliyorsa galeriden multiple selection aktif olsun.

Kullanıcı aynı anda birden fazla fotoğraf seçebilsin.

Ancak:

mevcut fotoğraf sayısı + yeni seçilen fotoğraf sayısı

10'u geçemez.

Örnek:

Mevcut 8 fotoğraf varsa ve kullanıcı 5 fotoğraf seçerse yalnızca izin verilen maksimum sınırı doğru yönet.

Tercihen kullanıcıya:

"En fazla 2 fotoğraf daha ekleyebilirsiniz."

uyarısı göster.

Veri state'ini 10'dan fazla fotoğrafla doldurma.

==================================================
9. FOTOĞRAF STATE YÖNETİMİNİ DÜZELT
==================================================

Mevcut ve yeni eklenen fotoğrafları doğru şekilde yönet.

Sadece string URI array kullanmak mevcut backend yapısı için yetersizse typed photo model oluştur.

Örneğin proje mimarisine uygun bir yapı:

type ListingPhoto = {
  id?: string;
  uri: string;
  remoteUrl?: string;
  isLocal: boolean;
  isCover?: boolean;
  sortOrder: number;
};

Ancak mevcut type sistemini gereksiz yere kırma.

Mevcut veri modelini incele.

Fotoğrafları şu şekilde ayırt edebil:

- Backend'den gelen mevcut remote fotoğraf
- Yeni seçilen local fotoğraf
- Silinmek için işaretlenen mevcut fotoğraf

Edit ekranında mevcut remote fotoğrafları yeniden upload etme.

Sadece yeni local fotoğrafları upload et.

==================================================
10. KAPAK FOTOĞRAFI MANTIĞI
==================================================

Mevcut UI'da ilk fotoğraf üzerinde:

KAPAK

etiketi bulunuyor.

Bu mantığı gerçek veri sırasına bağla.

Fotoğraf listesindeki index 0:

kapak fotoğrafı olacak.

İlk fotoğraf:

isCover = true

diğer fotoğraflar:

isCover = false

mantığında backend model destekliyorsa güncellensin.

Backend ayrı cover field kullanıyorsa mevcut veri şemasına göre doğru alanı güncelle.

Hardcoded ilk görsele "KAPAK" etiketi koyup backend'de farklı fotoğrafı kapak bırakma.

UI ve database aynı source of truth kullanmalı.

11. FOTOĞRAF SİLME
==================================================

Fotoğraf üzerindeki X butonu gerçek şekilde çalışmalı.

X butonuna basıldığında:

- doğru fotoğraf kaldırılmalı
- yanlış index silinmemeli
- photos state güncellenmeli
- sayaç güncellenmeli
- UI re-render edilmeli

Kapak fotoğrafı silinirse:

kalan fotoğraf listesinin ilk fotoğrafı otomatik kapak olmalı.

Örnek:

Fotoğraflar:

A [KAPAK]
B
C

A silinirse:

B [KAPAK]
C

olmalı.

Mevcut remote fotoğraf siliniyorsa database/storage cleanup mantığını kontrol et.

Storage'dan hemen silmek mevcut save/cancel davranışını bozuyorsa önce pendingDelete listesine ekle.

Kullanıcı Kaydet dediğinde gerçek silme işlemini tamamla.

Kullanıcı düzenleme ekranını kaydetmeden kapatırsa mevcut ilan fotoğraflarını yanlışlıkla storage'dan silme.

19. UPLOAD VE SAVE FLOW
==================================================

En kritik bölüm:

Fotoğraf UI'da görünmesine rağmen Kaydet sonrası kaybolmamalı.

Kaydet butonuna basıldığında:

1. Form validation çalışır.
2. Yeni local fotoğraflar belirlenir.
3. Yeni fotoğraflar storage'a upload edilir.
4. Upload URL/path sonuçları alınır.
5. Mevcut remote fotoğraflarla birleştirilir.
6. Silinen fotoğraflar sonuç listesinden çıkarılır.
7. Fotoğraf sırası korunur.
8. Kapak fotoğrafı doğru belirlenir.
9. Listing database row / related photo table güncellenir.
10. UI success state'e geçer.
11. Cache invalidate / refetch edilir.
12. İlan detay ekranı güncel fotoğrafları gösterir.
13. İlanlarım kartı yeni kapak fotoğrafını gösterir.
14. Düzenleme ekranına tekrar girildiğinde fotoğraflar doğru sırada gelir.

Upload tamamlanmadan ilan update mutation'ı çalıştırıp local file URI'lerini database'e yazma.

Database'e:

file://
blob:
content://

gibi local temporary URI kaydetme.

Database/storage sisteminde sadece kalıcı URL veya mevcut proje modeline uygun storage path sakla.

20. SUPABASE STORAGE KULLANILIYORSA
==================================================

Projede Supabase Storage kullanılıyorsa mevcut bucket yapısını tespit et.

Yeni rastgele bucket oluşturma.

Mevcut listing/adoption/listing-images bucket veya storage helper yapısını kullan.

Upload path collision oluşturma.

Unique path kullan.

Örnek mantık:

userId/listingId/uuid.extension

Ancak mevcut proje storage convention'ına uy.

Authentication user id doğrulamasını kullan.

Storage policy / RLS problemi varsa tespit et.

Upload sırasında 401 / 403 varsa UI handler'ı bypass etmek yerine gerçek auth/storage policy problemini raporla ve proje kapsamında güvenli şekilde düzelt.

Public bucket veya signed URL kullanım kararını mevcut mimariye göre koru.

Güvenliği düşürmek için tüm storage policy'leri public write yapma.
