Create one handler and use it for every add-pet button.

Required flow:

async function handleAddPet() {
  if (isCheckingPetAccess) return;

  setIsCheckingPetAccess(true);

  try {
    const status = await refreshPetPremiumStatus();

    if (status.canAddPet) {
      router.push("/evcilim/add");
    } else {
      router.push({
        pathname: "/evcilim-premium",
        params: {
          source: "add_pet",
          returnTo: "/evcilim/add"
        }
      });
    }
  } finally {
    setIsCheckingPetAccess(false);
  }
}

STEP 5 — SERVER-SIDE PET CREATION RULE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

The API must enforce the rule before inserting a pet.

Required server flow:

1. Authenticate the request.
2. Get the authenticated user ID from the verified session/token.
3. Count pets owned by that user directly in PostgreSQL.
4. Get server-authoritative Evcilim Premium status.
5. Get the user’s effective/grandfathered limit.
6. Reject the request when Premium is required.
7. Insert only when access is allowed.

Pseudo code:

const FREE_PET_LIMIT = 1;

const petCount = await countPetsForUser(authenticatedUserId);
const isPremium = await getServerVerifiedEvcilimPremiumStatus(
  authenticatedUserId
);

const effectivePetLimit = Math.max(
  FREE_PET_LIMIT,
  grandfatheredPetLimit ?? FREE_PET_LIMIT
);

const canAddPet =
  isPremium ||
  petCount < effectivePetLimit;

if (!canAddPet) {
  return res.status(402).json({
    code: "PET_PREMIUM_REQUIRED",
    message: "Evcilim Premium is required to add another pet.",
    petCount,
    freePetLimit: FREE_PET_LIMIT,
    effectivePetLimit,
    canAddPet: false
  });
}

Only after this check may the API insert the pet.

The check and insert should be transaction-safe.

Prevent two simultaneous requests from bypassing the limit and creating duplicate second pets.

Do not use a count provided by the mobile application.
