1. ZORUNLU TEST DOĞRULAMA KURALI
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Bir özelliği yalnızca kodunu inceleyerek PASS olarak işaretleme.

PASS verilebilmesi için:

1. Özellik gerçekten çalıştırılmış olmalı.
2. İlgili kullanıcı aksiyonu uygulanmış olmalı.
3. Beklenen UI sonucu görülmüş olmalı.
4. Backend işlemi varsa API sonucu doğrulanmış olmalı.
5. Veritabanı işlemi varsa veritabanında doğrulanmış olmalı.
6. Console veya network üzerinde beklenmeyen hata bulunmamalı.
7. Test sonrası kalıcı veri yeniden okunarak doğrulanmalı.
8. İlgili platformda gerçekten çalıştırılmış olmalı.

Sadece kod incelemesi yapılan sonuçlar:

STATIC REVIEW

olarak işaretlenmeli.

Platform veya özellik çalıştırılamıyorsa:

BLOCKED

Test yapılmadıysa:

NOT TESTED

Test yapıldı ancak başarısızsa:

FAIL

olarak raporlanmalı.

Android testi yapmadan Web sonucunu Android PASS kabul etme.

iOS testi yapmadan Android veya Web sonucunu iOS PASS kabul etme.

Expo Web önizlemesini native mobil testi olarak kabul etme.

Emülatör testini gerçek cihaz testi olarak raporlama.

Kamera, fotoğraf izinleri, bildirim, Apple ile giriş ve ödeme gibi fiziksel cihaz gerektiren özellikleri cihaz olmadan PASS gösterme.

Her PASS sonucu için şu kanıtları ekle:

- Çalıştırılan komut
- Test tarihi ve saati
- Platform
- Cihaz veya emülatör bilgisi
- Kullanılan test hesabı
- Test adımları
- Beklenen sonuç
- Gerçek sonuç
- İlgili console logu
- API sonucu
- Veritabanı doğrulaması
- Ekran görüntüsü veya test çıktısı varsa referansı

Kanıtı olmayan test sonucu PASS sayılmayacaktır.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
2. DENETİM ÇALIŞMA MODELİ

11. Düzeltmeyi uygula
12. Aynı testi yeniden çalıştır
13. Ortak altyapıyı kullanan diğer ekranları tara
14. Regression testi yap
