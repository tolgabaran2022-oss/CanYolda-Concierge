Akış sayfasındaki “Takip Ettiklerin” sekmesi yanlış çalışıyor. Kullanıcı başka profilleri takip ettiği halde bu sekmede “Henüz kimseyi takip etmiyorsun” boş durumu gösteriliyor.

Bu alanı Instagram mantığında gerçek takip sistemiyle çalışır hale getir.

AMAÇ:
Giriş yapan kullanıcının takip ettiği kişilerin paylaşımları “Takip Ettiklerin” sekmesinde görünmeli. Kullanıcı gerçekten kimseyi takip etmiyorsa ancak o zaman boş durum gösterilmeli.

YAPILACAKLAR:

1. Mevcut kullanıcıyı doğru al

const {
  data: { user },
} = await supabase.auth.getUser();

if (!user) return;

Giriş yapan kullanıcının auth.users.id değeri kullanılmalı.

2. Takip tablosunu kontrol et

Takip sistemi için kullanılan tabloyu tespit et. Tablo adı aşağıdakilerden biri olabilir:

- follows
- followers
- user_follows
- profile_follows

Tablo alanları şu mantıkta olmalı:

- id
- follower_id
- following_id
- created_at

Anlamları:

- follower_id: takip eden kullanıcı
- following_id: takip edilen kullanıcı

Giriş yapan kişinin takip ettiklerini çekerken yanlışlıkla following_id üzerinden sorgu yapma.

Doğru sorgu mantığı:

const { data: followRows, error: followError } = await supabase
  .from('follows')
  .select('following_id')
  .eq('follower_id', user.id);

if (followError) {
  console.error('Takip listesi alınamadı:', followError);
}

3. Takip edilen kullanıcı kimliklerini çıkar

const followingIds =
  followRows?.map((item) => item.following_id).filter(Boolean) || [];

console.log('Giriş yapan kullanıcı:', user.id);
console.log('Takip edilen kullanıcılar:', followingIds);

Takip kaydı varsa boş ekran gösterme.

4. Takip edilen kişilerin gönderilerini getir

Takip edilen kişilerin gönderilerini posts tablosundan çek.

const { data: posts, error: postsError } = await supabase
  .from('posts')
  .select(`
    id,
    user_id,
    content,
    caption,
    image_url,
    media_url,
    created_at,
    profiles:user_id (
      id,
      username,
      full_name,
      avatar_url
    )
  `)
  .in('user_id', followingIds)
  .order('created_at', { ascending: false });

Projede kullanılan gerçek sütun adlarını kontrol et. image_url yerine media_url veya post_images kullanılıyorsa mevcut yapıya göre uyarla.

Sahte gönderi oluşturma. Gerçek Supabase verilerini kullan.

5. Boş durum kontrolünü doğru yap

Şu anda muhtemelen posts.length === 0 olduğunda doğrudan “Henüz kimseyi takip etmiyorsun” mesajı gösteriliyor. Bu yanlış.

İki farklı boş durum oluştur:

A) Kullanıcı hiç kimseyi takip etmiyorsa:

followingIds.length === 0

Mesaj:

Başlık:
“Henüz kimseyi takip etmiyorsun”

Açıklama:
“Keşfet’ten yeni dostlar bulabilirsin.”

Buton:
“Keşfet’e Bak”

B) Kullanıcı birilerini takip ediyor fakat takip edilen kişiler henüz gönderi paylaşmadıysa:

followingIds.length > 0 && posts.length === 0

Mesaj:

Başlık:
“Henüz yeni gönderi yok”

Açıklama:
“Takip ettiğin kişiler paylaşım yaptığında burada göreceksin.”

Bu durumda “kimseyi takip etmiyorsun” mesajını gösterme.

Örnek render mantığı:

if (isLoading) {
  return <FeedSkeleton />;
}

if (followingIds.length === 0) {
  return <NotFollowingAnyone />;
}

if (followingIds.length > 0 && followingPosts.length === 0) {
  return <NoFollowingPosts />;
}

return <PostList posts={followingPosts} />;

6. Takip işlemi yapıldığında veriyi anında güncelle

Kullanıcı başka bir profilde “Takip Et” butonuna bastığında follows tablosuna gerçek kayıt eklenmeli.

const { error } = await supabase
  .from('follows')
  .insert({
    follower_id: currentUser.id,
    following_id: targetUserId,
  });

Aynı kişiyi tekrar takip etmeyi önlemek için unique constraint veya kontrol ekle:

unique(follower_id, following_id)

Kullanıcı takipten çıkarsa kayıt silinmeli:

const { error } = await supabase
  .from('follows')
  .delete()
  .eq('follower_id', currentUser.id)
  .eq('following_id', targetUserId);

7. Sekme açıldığında veriyi yeniden yükle

“Takip Ettiklerin” sekmesine her geçildiğinde takip listesi ve gönderiler yeniden çekilmeli.

React Native / Expo kullanılıyorsa:

- useFocusEffect
- useEffect
- RefreshControl

kullan.

Örnek:

useEffect(() => {
  if (activeTab === 'following') {
    loadFollowingFeed();
  }
}, [activeTab]);

Sekme daha önce boş açılmış olsa bile takip işleminden sonra tekrar açıldığında doğru veriler görünmeli.

8. Supabase Realtime desteği ekle

Takip edilen kişi yeni gönderi paylaştığında akış otomatik güncellensin.

supabase
  .channel('following-feed')
  .on(
    'postgres_changes',
    {
      event: 'INSERT',
      schema: 'public',
      table: 'posts',
    },
    () => {
      loadFollowingFeed();
    }
  )
  .subscribe();

Component unmount olduğunda channel kaldırılmalı.

9. RLS policy kontrolü

follows tablosunda giriş yapan kullanıcı kendi takip kayıtlarını okuyabilmeli.

Örnek SELECT policy:

create policy "Users can read follow relationships"
on public.follows
for select
to authenticated
using (
  follower_id = auth.uid()
  or following_id = auth.uid()
);

Takip oluşturma policy:

create policy "Users can follow profiles"
on public.follows
for insert
to authenticated
with check (
  follower_id = auth.uid()
);

Takipten çıkma policy:

create policy "Users can unfollow profiles"
on public.follows
for delete
to authenticated
using (
  follower_id = auth.uid()
);

posts tablosunda authenticated kullanıcılar yayınlanmış gönderileri okuyabilmeli.

profiles tablosunda username, avatar_url ve full_name alanları okunabilmeli.

RLS sebebiyle boş data geliyorsa policy’leri düzelt.

10. Profil kimliği ile auth kullanıcı kimliğini karıştırma

Projede profiles.id ile auth.users.id aynıysa user.id doğrudan kullanılabilir.

Eğer profiles tablosunda ayrı bir profile id kullanılıyorsa önce mevcut profil kaydını çek:

const { data: currentProfile } = await supabase
  .from('profiles')
  .select('id, user_id')
  .eq('user_id', user.id)
  .single();

Takip tablosunun auth user id mi yoksa profile id mi kullandığını belirle ve bütün takip işlemlerinde aynı kimlik tipini kullan.

En önemli kontrol:
Takip eklerken kullanılan ID ile takip listesini sorgularken kullanılan ID aynı sistemden gelmeli.

const handleExplorePress = () => {

16. Olası mevcut hataları özellikle kontrol et

Aşağıdaki hatalardan biri varsa düzelt:

- follower_id ve following_id ters kullanılıyor.
- Auth user ID yerine yanlış profile ID kullanılıyor.
- Takip kaydı sadece local state’e ekleniyor, Supabase’e kaydedilmiyor.
- Sekme açıldığında sorgu yeniden çalışmıyor.
- RLS follows kayıtlarını gizliyor.
- posts sorgusunda yanlış user_id alanı kullanılıyor.
- Takip edilen kullanıcılar var ama posts boş olduğu için yanlış boş durum gösteriliyor.
- activeTab değeri yanlış karşılaştırılıyor.
- FlatList’e yanlış data veriliyor.
- Takip sonrası cache temizlenmiyor.
- Query key invalidate edilmiyor.
- Filtre mevcut kullanıcının gönderilerini getiriyor ancak takip edilenleri getirmiyor.

17. React Query kullanılıyorsa cache’i düzelt

Takip etme veya takipten çıkma işleminden sonra:

queryClient.invalidateQueries({
  queryKey: ['following-feed', currentUser.id],
});

queryClient.invalidateQueries({
  queryKey: ['following-list', currentUser.id],
});

Sekmeye dönünce stale veri yerine güncel veri alınmalı.
