Fix the camera functionality on the “Report Animal Condition / Hayvan Durumu Bildir” form in the CanYoldaşı application.

CURRENT BEHAVIOR

1. The “Hayvan Durumu Bildir” button correctly opens the “Sokak Hayvanı Bildir” page.
2. The form contains a required “Fotoğraf Çek” area.
3. Clicking or tapping this area does not open the camera.
4. On WEB, the form displays:
   “iOS veya Android uygulamasını kullanın.”
5. The feature currently prevents web users from capturing the required photo and completing the report.

EXPECTED BEHAVIOR

The “Fotoğraf Çek” area must open the device camera on:

- Web browsers
- Android
- iOS

This report requires a current photo taken at the scene. Do not silently replace the camera-only rule with unrestricted gallery selection.

TASK 1 — FIND THE ROOT CAUSE

Inspect the current implementation and determine:

- Whether the photo area has a working `onPress` handler.
- Whether a transparent view or disabled state blocks clicks.
- Whether camera access is intentionally disabled through `Platform.OS === 'web'`.
- Whether the camera function returns early on web.
- Whether `expo-image-picker`, `expo-camera`, an HTML file input, or another camera library is being used.
- Whether required camera permissions are declared and requested.
- Whether the application is running in a secure context required by browsers.
- Whether an error is being caught without being shown or logged.

Do not apply a visual-only change. Prove why the camera is not opening.

TASK 2 — IMPLEMENT WEB CAMERA CAPTURE

Make camera capture work on the web.

Use the most reliable approach compatible with the existing Expo/React Native Web architecture.

Preferred behavior:

1. When the user clicks “Fotoğraf Çek,” request camera permission.
2. Open the available device camera.
3. Prefer the rear/environment-facing camera on supported devices.
4. Allow the user to take one current photo.
5. Return the captured file to the form.
6. Display a preview inside the photo area.
7. Allow the user to retake the photo before submitting.

A valid web implementation may use:

- A web-compatible existing Expo camera implementation, or
- `navigator.mediaDevices.getUserMedia()`, or
- A hidden HTML file input configured with:
  - `type="file"`
  - `accept="image/*"`
  - `capture="environment"`

Do not use a normal unrestricted gallery picker if camera-only capture can be enforced by the browser.

Web camera access requires HTTPS or localhost. Detect insecure contexts and show a clear user-facing message instead of failing silently.

TASK 3 — IMPLEMENT NATIVE CAMERA CAPTURE

For Android and iOS:

1. Request camera permission at runtime.
2. If permission is granted, launch the native camera.
3. If permission is denied, show a clear Turkish explanation.
4. Provide a button that allows the user to retry the permission request.
5. If permission is permanently blocked, provide an “Ayarları Aç” action that opens the application settings.
6. Prefer the rear camera.
7. Do not open the gallery from the “Fotoğraf Çek” action.
8. Do not break the existing navigation or form state.

Confirm the required native permission configuration exists:

Android:

- Camera permission in the application configuration.
- Correct Expo config/plugin settings if Expo is used.

iOS:

- A valid camera usage description.
- Correct Expo config/plugin settings if Expo is used.

Use a Turkish permission description suitable for App Store review, for example:

“Yakındaki sokak hayvanlarının durumunu fotoğraflayarak bildirebilmeniz için kamera erişimi gereklidir.”

TASK 4 — HANDLE THE CAPTURED IMAGE CORRECTLY

After capture:

- Show the real photo preview.
- Preserve the correct image orientation.
- Do not stretch or distort the image.
- Use `resizeMode="cover"` where appropriate.
- Store the correct URI/File/Blob according to the platform.
- Do not lose the photo when another form field is changed.
- Allow “Yeniden Çek.”
- Prevent multiple rapid clicks from opening multiple camera sessions.
- Canceling the camera must return safely to the form.
- Canceling must not crash the application or erase other form fields.

The submit button must remain disabled when no valid photo has been captured.

TASK 5 — UPLOAD AND PERSIST THE PHOTO

When the report is submitted:

1. Upload the captured photo to the correct Supabase Storage bucket.
2. Verify that a real file is created.
3. Save a permanent storage path or public URL in the report record.
4. Never save a temporary value such as:
   - `file://`
   - `content://`
   - `blob:`
   - A temporary browser preview URL
5. Confirm that the saved image appears on the animal status card after submission.
6. Refresh the page and verify that the image remains visible.
7. Re-read the saved database record and verify persistence.

On web, correctly convert the captured image into a `File` or `Blob` with:

- A valid MIME type
- A valid extension
- A unique safe filename

Revoke temporary object URLs when they are no longer required, but not before upload or preview has completed.

TASK 6 — USER-FACING ERROR STATES

Show clear Turkish messages for these conditions:

Camera permission denied:

“Kamera erişimi olmadan hayvan durumu bildirilemez. Lütfen kamera izni verin.”

No camera available:

“Bu cihazda kullanılabilir bir kamera bulunamadı.”

Camera already in use:

“Kamera başka bir uygulama tarafından kullanılıyor. Lütfen diğer uygulamayı kapatıp tekrar deneyin.”

Capture failed:

“Fotoğraf çekilemedi. Lütfen tekrar deneyin.”

Upload failed:

“Fotoğraf yüklenemedi. İnternet bağlantınızı kontrol edip tekrar deneyin.”

Do not expose technical stack traces, Supabase details, or secret information to users.
