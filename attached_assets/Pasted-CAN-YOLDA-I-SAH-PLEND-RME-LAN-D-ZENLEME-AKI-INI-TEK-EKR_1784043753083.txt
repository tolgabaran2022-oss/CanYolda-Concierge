CAN YOLDAŞI — SAHİPLENDİRME İLAN DÜZENLEME AKIŞINI TEK EKRANDA BİRLEŞTİR

Bu görevde yeni bir tasarım üretme.

Mevcut çalışan Sahiplendirme sistemini ve mevcut premium mor/lila UI tasarımını koru.

Amaç:
Sahiplendirme ilanı için uygulamada bulunan iki farklı "ilan düzenleme" akışını kaldır ve tüm uygulamada yalnızca TEK bir ortak ilan düzenleme ekranı kullan.

ÖNEMLİ:
Bu bir görsel redesign görevi değildir.
Mevcut tasarımı bozma.
Mevcut Sahiplendirme ilan düzenleme ekranını referans al.
Sadece duplicate/farklı edit akışlarını tek source of truth altında birleştir.

==================================================
1. MEVCUT SORUN
==================================================

Şu anda aynı Sahiplendirme ilanı iki farklı noktadan düzenlenebiliyor:

AKIŞ A:

Sahiplendirme
→ İlanlarım
→ İlan kartı
→ "Düzenle"
→ İlanı Düzenle ekranı

AKIŞ B:

Sahiplendirme
→ İlanlarım
→ İlan kartı
→ "Önizle"
→ Önizleme Modu / ilan detay ekranı
→ "İlanı Düzenle"
→ Farklı bir düzenleme sayfası veya farklı edit flow

Bu yanlış.

Aynı ilan için iki ayrı edit ekranı, iki ayrı UI veya iki ayrı form mantığı bulunmamalı.

==================================================
2. İSTENEN SONUÇ
==================================================

Uygulamada Sahiplendirme ilanlarını düzenlemek için yalnızca TEK bir ortak ekran bulunacak.

Örneğin mevcut proje mimarisine uygun isim kullan:

EditAdoptionListingScreen

veya mevcut projede kullanılan naming convention neyse onu koru.

Yeni ve gereksiz bir ekran oluşturma.

Mevcut çalışan ana düzenleme ekranını belirle ve bunu SINGLE SOURCE OF TRUTH yap.

Aşağıdaki iki buton da AYNI ekranı açmalı:

1. İlanlarım kartındaki "Düzenle" butonu

2. Önizleme Modu ekranının altındaki "İlanı Düzenle" butonu

Navigation sonucu birebir aynı olmalı:

→ Düzenle

Önizleme Modu
→ İlanı Düzenle
→ Shared Edit Adoption Listing Screen

Her iki akış da aynı listingId / adoptionListingId değerini taşımalı.

15. OWNER SECURITY
==================================================

Edit ekranı açılırken ilan sahipliğini doğrula.

Authenticated user yalnızca kendi Sahiplendirme ilanını düzenleyebilmeli.

Kontrol:

listing.owner_id === currentUser.id

veya projedeki gerçek owner field hangisiyse onu kullan.

Client-side check tek güvenlik katmanı olmasın.

Supabase kullanılıyorsa ilgili adoption listings table için UPDATE RLS policy'yi audit et.

Authenticated user yalnızca kendi ilanını update edebilmeli.

Örnek mantık:

auth.uid() = owner_id

Ancak mevcut table ve column isimlerini incelemeden migration yazma.

Önce gerçek schema'yı doğrula.

Mevcut güvenli RLS policy varsa gereksiz şekilde değiştirme.

==================================================
16. TYPE SAFETY
==================================================

TypeScript hatası bırakma.

Route params typed olsun.

Örneğin proje mimarisine uygun şekilde:

type EditAdoptionListingParams = {
  listingId: string;
};

listingId undefined olduğunda ekran crash olmamalı.

Missing ID durumunda:

- loading loop oluşturma
- boş form açma
- yanlış ilana fallback yapma

Güvenli error state göster ve geri dönüş imkanı sun.

No any abuse.

Yeni @ts-ignore veya @ts-nocheck ekleme.
