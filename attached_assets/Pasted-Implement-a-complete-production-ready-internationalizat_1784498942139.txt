Implement a complete, production-ready internationalization system for the entire CanYoldaşı application.

The language selector must first appear on the Login screen, but the selected language must change the language of the ENTIRE application.

Start with:

- Turkish: tr
- English: en

IMPORTANT:

- Do not translate only the Login screen.
- Do not create a screen-specific language state.
- Build one global language system shared by all screens.
- Do not redesign unrelated screens.
- Do not remove or break existing functionality.
- Do not reset or delete existing database data.
- Do not translate user-generated content automatically.
- Preserve all existing routes, API integrations and business logic.

3. TRANSLATION ARCHITECTURE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Create a clean structure similar to:

artifacts/mobile/i18n/
  index.ts
  resources/
    tr.json
    en.json

If the project structure requires a different location, follow the existing alias and folder conventions.

The i18n system must:

- Initialize before the main application UI is shown.
- Avoid displaying translation keys during startup.
- Use Turkish as the fallback language.
- Support runtime language switching.
- Persist the selected language.
- Restore the persisted language after app restart.
- Use the device language on the first launch.
- Fall back to Turkish if the device language is unsupported.
- Normalize language codes such as:
  - tr-TR → tr
  - en-US → en
  - en-GB → en
- Support adding more languages later.
- Never crash because of a missing translation.
- Log missing development translations without exposing them to users.

Recommended configuration:

fallbackLng: "tr"
supportedLngs: ["tr", "en"]
load: "languageOnly"
interpolation.escapeValue: false
returnNull: false

Use complete natural translations, not machine-like word-for-word text.

9. TRANSLATION-KEY RULES
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Use semantic, structured translation keys.

Good examples:

common.save
common.cancel
common.loading
auth.login.title
auth.login.emailPlaceholder
auth.errors.invalidCredentials
navigation.map
navigation.animals
map.nearbyAnimals
streetAnimals.status.hungry
adoption.createListing
pets.add.title
pets.empty.title
premium.restorePurchases
account.language

Do not use Turkish sentences as keys.

Bad:

t("Kaydet")
t("Evcil hayvan ekle")

Good:

t("common.save")
t("pets.add.title")

Use interpolation for dynamic values:

t("pets.count", { count: petCount })
t("heroes.monthlyScore", { score })
t("time.minutesAgo", { count: minutes })

Use i18next pluralization for singular/plural content.

Do not build translated sentences by concatenating fragments.
