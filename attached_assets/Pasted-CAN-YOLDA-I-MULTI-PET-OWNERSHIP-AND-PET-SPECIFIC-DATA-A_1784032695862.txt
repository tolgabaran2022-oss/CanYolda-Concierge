==================================================
REALTIME SYNCHRONIZATION
==================================================

If Supabase Realtime is used:

INSERT pet:
Add the new pet to the pets array.

UPDATE pet:
Update only the matching pet by ID.

DELETE pet:
Remove only the matching pet by ID.

Conceptual logic:

INSERT:

setPets(previous =>
  previous.some(pet => pet.id === newPet.id)
    ? previous
    : [...previous, newPet]
);

UPDATE:

setPets(previous =>
  previous.map(pet =>
    pet.id === updatedPet.id
      ? updatedPet
      : pet
  )
);

DELETE:

setPets(previous =>
  previous.filter(pet => pet.id !== deletedPet.id)
);

Never use:

setPets([payload.new])

because this removes all other pets.

Deduplicate realtime events using pet ID.

RLS SECURITY
==================================================

Audit Supabase Row Level Security.

A user may SELECT pets they own.

Example conceptual rule:

owner_id = auth.uid()

A user may INSERT a pet only when:

owner_id = auth.uid()

A user may UPDATE or DELETE a pet only when:

owner_id = auth.uid()

For pet-specific child records:

The user can access a record only when the associated pet belongs to them.

Conceptually:

EXISTS (
  SELECT 1
  FROM pets
  WHERE pets.id = child_table.pet_id
  AND pets.owner_id = auth.uid()
)

Do not trust a client-provided owner_id alone.

Do not allow User A to manually change pet_id and access User B's pet records.
