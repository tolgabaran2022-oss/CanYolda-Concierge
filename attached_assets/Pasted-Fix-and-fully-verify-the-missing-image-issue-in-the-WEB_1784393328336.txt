Fix and fully verify the missing image issue in the WEB version of the CanYoldaşı application.

CURRENT ISSUE

1. Images are not visible on the status cards on the “Animals” page.
2. Pet photos are not visible in the “My Pet / Evcilim” section.
3. Text, status, user, and location data load correctly, but image areas remain as empty purple placeholders.
4. The problem is specifically visible on WEB.
5. Do not break the existing Android or iOS behavior.

TASK 1 — INSPECT THE REAL DATA FLOW

Identify and inspect:

- The photo field used by the status cards.
- The photo field used by pet records.
- The actual values stored in the Supabase database.
- Whether each value is:
  - A complete URL
  - A Supabase Storage path
  - A string
  - An array
  - A JSON string
  - An object

Compare the database column names with the frontend field names.

Check for mismatches such as:

- `image_url`
- `imageUrl`
- `photo_url`
- `photoUrl`
- `image`
- `photo`
- `photos`
- `images`

Do not assume the data structure. Confirm it using real database records.

TASK 2 — CHECK SUPABASE STORAGE

- Identify and verify the exact bucket names.
- Confirm that the files actually exist in the expected buckets.
- If the bucket is public, convert storage paths into valid HTTPS URLs using `getPublicUrl()`.
- If the database already contains a complete `http://` or `https://` URL, do not pass it through `getPublicUrl()` again.
- If the bucket is private, generate valid signed URLs.
- If signed URLs have expired, regenerate them when the list is loaded.
- Open at least one real generated image URL directly in the browser.
- Verify whether it returns the actual image.

Check for:

- Incorrect bucket names
- Duplicate bucket names inside paths
- Missing or duplicated slashes
- Incorrect URL encoding
- Missing files
- Expired signed URLs
- Storage access policy errors
- HTTP URLs being blocked on an HTTPS page
- 401, 403, or 404 responses

TASK 3 — FIX WEB IMAGE RENDERING

Verify that React Native Web receives a valid image source:

`source={{ uri: finalImageUrl }}`

Make sure the final image URL is not:

- `undefined`
- `null`
- An empty string
- `[object Object]`
- A JSON string that was not parsed
- A local device URI such as `file://` or `content://`

Verify that the image container has an explicit width and height on WEB.

Check for styles that may hide the image:

- `display: none`
- `opacity: 0`
- Incorrect `zIndex`
- Incorrect absolute positioning
- Incorrect `overflow`
- A placeholder layer covering the image
- A platform condition that renders images only on native platforms

Use appropriate image styling where needed:

- `width: '100%'`
- `height: '100%'`
- `resizeMode="cover"`
- A valid `aspectRatio`

The placeholder must only appear when:

1. No valid image URL exists, or
2. The real image triggers `onError`.

The placeholder must not cover successfully loaded images.

TASK 4 — CREATE A SHARED IMAGE URL RESOLVER

Create one reusable and safe image URL resolver and use it for both:

- Animal status cards
- The “My Pet / Evcilim” section

The resolver must safely support:

- Complete HTTP/HTTPS URLs
- Supabase Storage paths
- A single string
- An array of strings
- A JSON-encoded string
- `{ url: string }`
- `{ uri: string }`
- `{ path: string }`
- Arrays containing objects

Expected behavior:

1. Extract the first valid image value.
2. Parse JSON only when appropriate.
3. Return complete HTTPS URLs unchanged.
4. Convert Supabase Storage paths using the correct bucket.
5. Reject invalid local device URLs on WEB.
6. Return `null` safely when no valid image exists.
7. Never crash because of malformed image data.

Do not duplicate URL conversion logic across multiple components.
