==================================================
2. REMOVE HEADER-BASED IDENTITY
==================================================

The following must never be accepted as authentication:

x-user-id
X-User-Id
custom user ID headers
query-string user IDs
request-body user IDs

A client must not be able to impersonate another user by sending an arbitrary ID.

Remove all backend authentication fallback behavior based on x-user-id.

Delete:

extractUserIdDual()

only after confirming there are zero remaining legitimate usages.

If the function is exported anywhere, remove stale exports and imports.

==================================================
3. JWT AUTHENTICATION STANDARD
==================================================

Protected routes must identify the authenticated user only from a valid JWT:

Authorization: Bearer <access_token>

Create or reuse one centralized authentication middleware.

Preferred behavior:

- read Authorization header
- require Bearer scheme
- verify signature
- verify expiry
- validate payload shape
- extract authenticated user ID
- attach authenticated identity to req.auth or equivalent typed location
- reject malformed or expired tokens
- never trust client-provided user ID as identity

Use the existing JWT_SECRET environment validation.

Do not create a second JWT implementation.

Do not decode without verifying.

==================================================
7. OWNERSHIP AUTHORIZATION
==================================================

Authentication alone is not enough.

For every update/delete route:

1. Verify JWT
2. Load target resource
3. Confirm resource owner equals authenticated user
4. Reject otherwise with 403
5. Perform mutation

Never trust:

req.body.userId
req.params.userId
req.query.userId
x-user-id

as proof of ownership.

They may identify a target resource, but authorization must always use the verified JWT identity.

Use:

401 Unauthorized:
missing, malformed or expired authentication

403 Forbidden:
valid user but not authorized for the resource

404 Not Found:
use consistently where hiding resource existence is appropriate
