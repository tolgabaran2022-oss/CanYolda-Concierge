CRITICAL PROJECT RULE:

EVERY new feature, bug fix, UI update, database integration, interaction logic, navigation change, component update, and design revision must be implemented and verified on:

- iOS Simulator
- Android Emulator
- Web Preview

A change must NEVER be considered complete if it only works or appears on one platform.

The same latest application version must always be visible and functional on iOS, Android, and Web.

==================================================
GLOBAL CROSS-PLATFORM RULE
==================================================

For every task I give you from now on:

1. Implement the requested update.
2. Verify the implementation on iOS.
3. Verify the same implementation on Android.
4. Verify the same implementation on Web.
5. Fix all platform-specific issues before reporting completion.

Do not say "completed" after testing only iOS.

The completion rule is:

iOS = Android = Web

in terms of:
- features
- business logic
- database data
- interactions
- navigation
- current UI version

==================================================
IOS IS NOT A SEPARATE APPLICATION
==================================================

Do not create features only inside:

*.ios.ts
*.ios.tsx
*.ios.js
*.ios.jsx

unless there is a real native technical requirement.

Do not place universal features behind:

Platform.OS === 'ios'

Do not use logic such as:

if (Platform.OS === 'ios') {
  return <NewFeature />
}

while Android or Web continue rendering the old implementation.

The application is a universal Expo / React Native application.

Universal features must live in shared files.

Preferred structure:

SharedScreen.tsx
SharedComponent.tsx
shared hooks
shared services
shared Supabase logic

Only native APIs may use small platform adapters.

==================================================
SHARED COMPONENT RULE
==================================================

For universal UI, always prefer one shared component.

BAD:

PetScreen.ios.tsx
PetScreen.android.tsx
PetScreen.web.tsx

with different versions of the same screen.

GOOD:

PetScreen.tsx

and only small adapters such as:

imagePicker.native.ts
imagePicker.web.ts

when platform APIs genuinely differ.

Do not maintain old screen copies for Android or Web.
