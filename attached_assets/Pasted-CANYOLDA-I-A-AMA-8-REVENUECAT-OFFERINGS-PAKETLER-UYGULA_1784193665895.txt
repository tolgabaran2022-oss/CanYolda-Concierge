3. PAKETLERİ DOĞRU EŞLEŞTİR
==================================================

Offering içindeki availablePackages listesini kullan.

Package identifier mapping:

boost_1_day
→ 1 Gün Öne Çıkar
→ durationDays: 1

boost_3_days
→ 3 Gün Öne Çıkar
→ durationDays: 3

boost_7_days
→ 7 Gün Öne Çıkar
→ durationDays: 7

Server tarafı ileride duration değerini product ID üzerinden doğrulayacak.

Bu aşamada UI mapping için merkezi bir config oluştur.

Örneğin:

const BOOST_PACKAGE_CONFIG = {
  boost_1_day: {
    durationDays: 1,
    title: "1 Gün Öne Çıkar",
  },
  boost_3_days: {
    durationDays: 3,
    title: "3 Gün Öne Çıkar",
    badge: "En Popüler",
  },
  boost_7_days: {
    durationDays: 7,
    title: "7 Gün Öne Çıkar",
  },
};

Magic stringleri farklı componentlere dağıtma.

==================================================

Hiç paket yoksa selectedPackage null olmalı.

Development ortamında güvenli hata kodu/message loglanabilir.

API key veya hassas satın alma verisi loglanmamalı.

11. REFRESH / SCREEN LIFECYCLE
==================================================

Ekran her render olduğunda RevenueCat’e gereksiz tekrar tekrar istek atma.

UseEffect dependency’lerini doğru kur.

React Strict Mode veya navigation remount durumunda duplicate fetch riskini azalt.

Ancak kullanıcı Retry butonuna basınca yeniden fetch yapılabilmeli.

Ekrana geri dönüldüğünde eski package state geçerliyse güvenli şekilde gösterilebilir.
