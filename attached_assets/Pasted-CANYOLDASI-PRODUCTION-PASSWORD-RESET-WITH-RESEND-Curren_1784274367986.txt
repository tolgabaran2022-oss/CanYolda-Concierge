2. DATABASE FOUNDATION
==================================================

Create a non-destructive password reset token table if one does not already exist.

Recommended structure:

password_reset_tokens

id uuid primary key
user_id foreign key to users
token_hash text not null unique
expires_at timestamptz not null
used_at timestamptz nullable
created_at timestamptz not null default now()
requested_ip text nullable
user_agent text nullable

Do not store the raw reset token in the database.

Generate a cryptographically secure random token.

Store only its SHA-256 hash.

Recommended token lifetime:

30 minutes

One token must be single-use.

When a new reset is requested, invalidate previous unused tokens for that user.

==================================================

}

- token unused
- token not expired
- passwords match
- password meets current production policy
- password is not excessively long
- password is not identical to obvious invalid defaults if the project has such checks

Recommended minimum:

Prefer requiring a reasonable combination according to the existing app UX, but do not create an unnecessarily hostile password policy.

Inside one database transaction:

2. update password hash using the existing secure hash algorithm
3. set used_at
4. invalidate all other unused reset tokens
5. revoke active refresh sessions/tokens where supported
6. commit

The same reset token must never work twice.
